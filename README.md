# ETF Portfolio Optimization Framework

This repository contains a modular Python framework for ETF universe construction, Bayesian/ML return forecasting, portfolio optimization, nested walk-forward selection, dynamic parameter control, transaction-cost-aware execution, and result visualization.

The framework is designed for monthly ETF rebalancing research. The main logic is:

1. clean daily ETF price data;
2. create monthly business rebalance dates;
3. generate ETF daily log returns and EWMA returns;
4. build a monthly investable ETF universe;
5. forecast future returns with Bayesian or ML models;
6. optimize long-only ETF weights with CVaR, Markowitz, Black-Litterman, or benchmark strategies;
7. select the best method by train -> validation -> internal test walk-forward logic;
8. execute the selected weights on the next out-of-sample month;
9. save PnL, model metrics, weights, dynamic parameters, and plots.

## 4. Main workflow

### Step 1 — Parse prices, create business dates, returns, and EWMA returns

```bash
python -m scripts.dataloader.parse_close
```

This reads `datasets/csv/NewClosePrice.csv` and saves:

```text
datasets/excel/business_dates.xlsx
datasets/excel/new.csv
datasets/excel/new_etf_returns.csv
datasets/excel/new_etf_ewma.csv
```

Main logic:

```text
log_return_{i,t} = log(P_{i,t} / P_{i,t-1})
EWMA = exponentially weighted mean of log returns
```

The script also filters to US business dates and fills missing values after each ETF starts trading.

---

### Step 2 — Build the ETF universe

#### Option A: liquidity-only monthly universe

```bash
python -m scripts.dataloader.filter_data
```

This uses:

```text
dollar_amount = ((close + open) / 2) * volume
```

It applies 36-month liquidity history and rolling liquidity-share threshold logic, then saves an Excel eligibility matrix such as:

```text
datasets/excel/final_filtered_weights.xlsx
```

#### Option B: improved momentum/liquidity/risk universe

```bash
python -m scripts.dataloader.new_filter_data
```

This adds:

- 12-month momentum;
- 3-month momentum;
- 6-month relative strength versus SPY;
- liquidity score;
- volatility penalty;
- drawdown penalty.

The scoring formula is approximately:

```text
Score = 0.35*z(mom_12m)
      + 0.25*z(mom_3m)
      + 0.20*z(relative_strength)
      + 0.15*z(liquidity)
      - 0.30*z(volatility_3m)
      - 0.15*z(abs(drawdown_6m))
```

It saves:

```text
datasets/excel/filtered_weights_1.xlsx
```

#### Option C: monthly metric filtration

```bash
python -m scripts.dataloader.monthly_etf_filtration \
  --prices datasets/csv/NewClosePrice.csv \
  --volumes datasets/csv/Volume.csv \
  --business-dates datasets/excel/business_dates.xlsx \
  --top-n 100 \
  --benchmark SPY \
  --spy-filter smart \
  --rolling-score-months 3 \
  --output-dir datasets/monthly_filtration
```

This computes ETF-level monthly metrics and saves:

```text
datasets/monthly_filtration/monthly_etf_scores.csv
datasets/monthly_filtration/top_etfs_long.csv
datasets/monthly_filtration/top_etfs_wide.csv
datasets/monthly_filtration/top_etfs_by_month.json
datasets/monthly_filtration/top_etfs_by_month.yaml
```

The active `monthly_etf_filtration.py` uses rolling aggregate score smoothing controlled by `--rolling-score-months`.

---

### Step 3 — Run the main optimizer

Bayesian CVaR run:

```bash
python -m scripts.runs.run --config-path bayessian_cvar.yaml
```

ML regression + CVaR run:

```bash
python -m scripts.runs.run --config-path ml_cvar.yaml
```

Test config:

```bash
python -m scripts.runs.run --config-path test.yaml
```

The main monthly loop in `scripts/runs/run.py` does the following:

1. reads business dates;
2. reads close prices and volumes;
3. builds `market_cap = price * volume` as liquidity proxy;
4. reads monthly eligible ETF sheets;
5. chooses ETFs with `Value = 1`;
6. extracts rolling/expanding historical returns;
7. updates optimizer parameters dynamically;
8. forecasts return scenarios;
9. runs nested train/validation/internal-test selection if enabled;
10. executes the selected portfolio on the next month;
11. saves results.

## 5. YAML configuration

Common top-level keys:

| Key | Meaning |
|---|---|
| `balance` | initial balance |
| `window` | `rolling` or `expanding` historical window |
| `lookback_years` | historical years used at each rebalance |
| `initial_weight` | `equal`, `random`, or `dirichlet` |
| `portfolio` | `filtered`, `sp500_all`, or `sp500_benchmark` |
| `use_backtest_engine` | enables nested method selection |
| `output_folder` | result folder under `results/` |
| `is_previous` | compares new target portfolio with current portfolio |
| `seed` | random seed |
| `model` | forecasting model config |
| `optimizer` | optimizer config |
| `execution` | execution and transaction cost config |

### Bayesian model example

```yaml
model:
  - type: bayessian
  - matrix_type: fast
  - mean_return: sampled
  - distribution: normal
  - posterior: horseshoe
  - n_samples: 1000
  - horizon: 21
  - cov_method: ledoit_wolf
  - random_state: 42
```

### ML model example

```yaml
model:
  - type: ml_regression
  - ml_type: lasso
  - horizon: 21
  - cv_splits: 3
  - n_samples: 1000
  - random_state: 42
```

Supported ML types:

```text
ridge, lasso, linear, random_forest
```

### Optimizer example

```yaml
optimizer:
  - type: bayessian
    min_weight: 0.005
    max_weight: 0.12
    task_type: "cvar_returns"
    confidence_level: 0.99
    turnover_penalty: 1.0
    penalty_type: L1
    is_all_methods: false
```

Supported optimizers:

| Type | File | Methods |
|---|---|---|
| `bayessian` | `optimizers/bayessian.py` | `cvar_returns`, `mean_cvar_sharpe`, `expected_returns`, `deviation_from_target`, `bayesian_sharpe` |
| `markowitz` | `optimizers/markowitz.py` | `max_sharpe`, `min_variance`, `max_return_min_vol`, `max_diversification`, `max_decorrelation` |
| `black_litterman` | `optimizers/black_litterman.py` | `black_litterman` |

### Execution example

```yaml
execution:
  - type: base_exec
    return_type: "log-returns"
    is_past: true
    use_dynamic_alpha: true
    c_bps: 1e-3
```

`c_bps` is multiplied by turnover:

```text
cost = c_bps * turnover
```

## 9. Core methodology in short

### Portfolio constraints

```text
w_i >= 0
sum_i w_i = 1
w_i <= max_weight
```

Small weights below `min_weight` are removed and the portfolio is renormalized.

### Execution

```text
w_exec = w_current + alpha * (w_target - w_current)
turnover = sum_i |w_exec_i - w_current_i|
cost = c_bps * turnover
monthly_return = product_t(1 + w_exec'R_t) - 1 - cost
```

### CVaR

```text
loss_s = -R_s w
CVaR_alpha = mean(loss_s in worst tail)
```

### Nested engine

For each rebalance month:

```text
train history -> validation months -> internal test months -> next true month
```

The engine keeps top validation candidates, retests them on the internal test split, selects the best candidate, and then executes the chosen portfolio on the next out-of-sample month.

## 10. Important notes

1. `test.yaml` contains duplicate `model:` blocks. YAML keeps the last one.
2. `run.py` hardcodes `last_filtered_weights.xlsx`; edit it if you want another universe.
3. Result scripts hardcode `folder_name`; edit before plotting.
4. `monthly_etf_filtration.py` contains an old commented version before the active implementation.
5. A target like annual return above 15% or Sharpe above 1 cannot be guaranteed by code alone; it must be validated through strict out-of-sample backtests.
6. For a publication, report benchmark comparisons, transaction-cost sensitivity, turnover, and robustness checks.
